# 公開・実機確認の記録

## 公開前の確認

GitHub Pages向けに `VITE_GITHUB_PAGES=true pnpm build` を実行し、`/tsundoku-dungeon/` を基準とする相対パスのビルドが成功することを確認した。現行のGitHub Pages公開版は `main` の内容を配信しており、Reader・遭遇UI・読書契約を含むDraft PRは、マージ後のデプロイで改めて確認する必要がある。

| 項目 | 現状 | 次の確認 |
|---|---|---|
| 開発用ビルド | `pnpm check` と `pnpm build` が成功 | PR更新時に再実行する。 |
| Pages用ビルド | `VITE_GITHUB_PAGES=true pnpm build` が成功 | PRマージ後、公開URLで画像とReaderを確認する。 |
| 公開版の応答 | 現行mainでタイトル画面の応答を確認 | 新規機能は未マージのため未反映。 |
| iOS / Android実機 | 未検証 | safe-area、Readerの慣性スクロール、スワイプ、ボトムシートを確認する。 |

## 手動スモークテスト

1. タイトルから探索を開始し、上下キー・W/S・方向パッド・スワイプが画面上の移動方向と一致することを確かめる。
2. 各章で出口へ向かう前に、未読時は「頁の鍵がない」と表示されることを確かめる。
3. 問いの本でReaderを開き、戻るだけでは鍵が閉じたままであることを確かめる。
4. Reader末尾の**本を閉じる**で鍵が開き、朱の栞と余白回復が反映されることを確かめる。
5. 問い以外の本でも鍵が開くこと、ただし朱の栞は得られないことを確かめる。
6. スマホ幅320px、375px、430pxで、目的表示と遭遇ボトムシートに横スクロールや操作の重なりがないことを確かめる。

## バンドル評価

Babylonの場面生成を初回探索から即座に使う現構成では、プロダクションビルドの主chunkは約1.7MB（gzip 約444KB）となり、Viteのサイズ警告が出る。現段階では、単純なchunk分割は初期ダウンロード量を減らさず、Readerへ入る前の探索開始遅延を増やす可能性があるため見送る。実機計測で初回表示が問題になった場合のみ、タイトル画面とBabylonシーンの遅延ロードを別Issueとして検討する。
